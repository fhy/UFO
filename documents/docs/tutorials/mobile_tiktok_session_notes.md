## 启动链路

完整调用链路如下：

```text
HTTP /api/dispatch
  -> UFO Server
  -> WebSocket
  -> Mobile Client
  -> Mobile MCP
  -> ADB
  -> Android device
  -> screenshot/UI controls
  -> llama-server vision model
  -> result callback
  -> HTTP /api/task_result/{task_name}
```

当前本地模型由 llama-server 提供：

```text

```

模型的 `multimodal` 能力已经通过 OpenAI 兼容接口验证，可以读取 PNG Base64 图片并识别中文、泰文、英文和价格。

## ADB 连接

Android USB 调试权限通过 udev 规则修复。正常状态应为：

```text
<serial> device usb:... model:... device:...
```

如果状态是 `unauthorized`，需要在手机上允许 USB 调试。如果设备进入无密码锁屏，可以使用：

```bash
adb shell input keyevent KEYCODE_WAKEUP
adb shell input swipe 360 1300 360 500 300
```

## 自动解锁

`ufo/client/mcp/http_servers/mobile_mcp_server.py` 中增加了动作前的设备状态检查。

目前以下动作执行前会检查锁屏状态：

- `tap`
- `swipe`
- `press_key`
- `click_control`

检测到 `mDreamingLockscreen=true`、`mShowingLockscreen=true` 或 `isStatusBarKeyguard=true` 时，会先发送唤醒事件并执行无密码上滑解锁，然后再执行原始动作。

这解决了手机在任务执行过程中自动息屏导致后续 ADB 动作失效的问题。它不能解决 TikTok 页面状态或 UI 控件缓存错位。

## 任务结果修复

### Session ID 一致性

以前 HTTP dispatch 返回的 session ID 与 Mobile Client 后续使用的 session ID 可能不一致。现在 Client 收到 Server 的 `TASK` 消息后，会保留 Server 分配的 `session_id`，确保：

- `/api/dispatch` 返回的 ID
- Server session
- Client task request
- Client command result

使用同一个 session ID。

修改位置：

```text
ufo/client/websocket.py
```

### 任务状态查询

`SessionManager` 现在按 task name 保存任务生命周期状态：

- `running`
- `done`
- `failed`

HTTP 查询规则：

- 正在执行：`{"status":"pending"}`
- 正常完成：`{"status":"done","result":...}`
- 执行失败或超时：`{"status":"failed","result":...}`

不再使用空数组判断任务是否完成，也不再仅通过已经清理的 session 对象反查结果。

修改位置：

```text
ufo/server/services/api.py
ufo/server/services/session_manager.py
```

### 任务超时和步数上限

系统配置中增加了任务硬超时：

```yaml
TASK_TIMEOUT: 900
MAX_STEP: 50
MAX_ROUND: 1
```

只因达到 `MAX_STEP` 而停止时，不再误报为成功，而是返回失败。这样可以区分 Agent 主动 `FINISH` 和达到安全上限。

## 失败原因总结

### UI 控件缓存错位

这是最主要的问题。TikTok 页面切换后，截图显示的页面和 UI 控件列表可能来自不同时间点。例如：

- 截图已经是商品列表
- 控件列表仍然是“分享主页”弹层
- Agent 因此点击了历史的“关闭”控件

后果包括进入：

- 分享主页
- 发现好友
- 二维码扫描
- 个人简介编辑页
- 视频或声音详情页

### LLM 坐标点击不稳定

商品卡片通常包含多个区域：

- 商品图片
- 商品标题
- 价格
- 购物车
- 立即购买
- 管理商品

模型生成的坐标可能点击到图片查看器或管理区域，而不是商品详情入口。提示词可以降低概率，但不能提供程序级保证。

### 长任务依赖模型记忆状态

商品遍历、详情页滚动次数、已检查商品和前后邻接商品都依赖模型在上下文中维护。页面发生偏移后，模型可能：

- 重复检查同一商品
- 在详情页超过预定滚动次数
- 返回次数过多
- 无法判断当前是否在商品列表
- 在最终统计前一直返回 `CONTINUE`

### 重复运行组件

多次手动启动会留下多个 Server、Client 或 MCP 进程。它们可能共享同一手机和端口，造成：

- 任务命令交错
- MCP 缓存互相污染
- Client 连接到旧 Server
- 任务结果和日志难以对应

排查时应确保每个端口只有一个监听进程，并且只有一个 `mobile_phone_1` Client。

### llama-server 请求耗时

视觉模型读取大截图时可能产生较长响应。日志中曾出现 API 请求超时，但 llama-server 本身仍可通过 `/v1/models` 正常响应。任务硬超时用于防止此类情况无限占用 session。

## 推荐操作流程

执行新的 TikTok 任务前：

1. 确认手机已连接且状态为 `device`。
2. 确认只有一套 MCP、Server、Client 进程。
3. 确认手机已唤醒并解锁。
4. 确认 TikTok 当前页面是个人主页或商品列表，而不是分享弹层、二维码或视频详情页。
5. 先执行只读诊断任务，重新采集截图和控件。
6. 进入商品详情后，允许固定次数的向下滚动。
7. 发现“达人视频精选”后立即停止滚动。
8. 只读取商品名称、价格、区域数量和第一个达人可见文字，不点击视频。
9. 任务完成后通过 `/api/task_result/{task_name}` 查询最终状态。

## TikTok 页面特征与跳转记录

下面的页面特征来自已成功找到“达人视频精选”的实际流程，以及后续失败任务中观察到的页面偏移。执行后续任务时，应把截图作为页面状态的主要依据，不能只依赖上一轮缓存的控件 ID。

### 个人主页

正常个人主页通常包含：

- 底部导航：`首页`、`商城`、`收件箱`、`主页`
- 个人资料区域、头像、用户名和粉丝/关注/获赞统计
- 个人主页上的 `商店` 或商品橱窗入口
- 商品卡片或 TikTok Shop 区域

如果页面只有视频流、声音详情或底部导航，没有个人资料区域，不应认为已经进入个人主页。应优先点击当前页面实时控件中的 `主页`，然后等待并重新采集截图和控件。

### 商品列表页

成功路径中的商品列表特征：

- TikTok Shop 或商品橱窗标题/横幅
- 多个商品卡片
- 商品名称、价格、折扣或销量
- 商品图片旁有标题/价格文字区域
- 底部导航仍可能显示 `首页`、`商城`、`收件箱`、`主页`

进入商品详情时，优先点击商品卡片的标题、价格或右侧文字区域。不要点击图片、购物车、购买或管理控件。商品图片区域经常会进入图片查看器，而不是商品详情页。

### 图片查看器

图片查看器的特征：

- 大图占据主要屏幕区域
- 顶部或左上角出现 `关闭`、返回箭头或类似关闭控件
- 通常没有商品详情标签、价格和购买区域

如果进入图片查看器，只允许点击一次当前页面实时采集到的 `关闭`，然后重新采集截图和控件。不要沿用进入前的控件 ID。

### 商品详情页

商品详情页通常包含：

- 商品完整或截断名称
- 当前价格、原价、折扣或包邮信息
- 商品详情标签，例如 `概述`、`评论`、`描述`、`推荐`
- 店铺、聊天、购买等商品操作
- 可垂直滚动的详情内容

已成功验证的详情页路径：

```text
商品列表
  -> 商品详情页
  -> 向下滚动 1 次
  -> 发现“达人视频精选 (13)”
  -> 停止滚动并读取商品信息
```

成功记录中的商品为：

```text
商品：ตุ๊กตา ai พูดได้
目标区域：达人视频精选 (13)
滚动次数：1
```

如果当前页面只有商品列表卡片，不能把它当作详情页；如果滚动后出现商品推荐网格但没有详情内容，也应停止继续盲目滚动并重新判断页面类型。

### 达人视频精选区域

目标必须匹配准确文字：

```text
达人视频精选
```

成功时页面显示为：

```text
达人视频精选 (13)
```

发现目标区域后：

1. 立即停止滚动。
2. 先读取商品名称和当前价格。
3. 如用户要求进入达人信息，再点击该区域中的第一个视频。
4. 进入视频页后只点击明确的达人头像或账号名称。
5. 达人主页只读取公开文字信息，不执行关注、点赞、评论或分享。

部分商品第一次向上滑动后仍不会显示目标区域。第一次未找到时，应再向上滑动一次并重新检查。之前的成功路径在一次向上滑动后看到 `达人视频精选 (13)`，另一次测试看到 `达人视频精选 (30+)`，最近一次完整流程在两次滑动后看到 `达人视频精选 (2)`。

标准查找动作是：商品卡片列表点击商品后，等待几秒让详情页加载，再在设备屏幕上向上滑动并逐次检查。第一次发现标题后，尽量通过一次受控滑动把 `达人视频精选` 移到屏幕中部偏上位置（720x1600 屏幕约 y=450-750），同时让第一条缩略图避开底部购买栏。标题已出现但缩略图被挡住时不能点击。部分商品可能直到第 3 次向上滑动才显示目标，因此应检查第 1、2、3 次滑动；页面到底或不再变化时提前停止。之前验证成功的是向上滑动 1 次出现 `达人视频精选 (13)`，另一次成功测试显示 `达人视频精选 (30+)`，也有商品在两次滑动后出现 `达人视频精选 (2)`。

页面顺序规则：相关商品详情布局中，`达人视频精选` 位于 `客户评论` 或 `客户对店铺的评价` 上方。如果已经看到客户评论区域但仍未找到目标，应立即终止当前商品的详情页搜索，不要继续向下滑动到评论下方，也不要点击评论卡片或评论视频。只有确认评论上方没有目标文字时，才能记录该商品没有达人视频精选；评论下方的普通 `视频` 区域不能替代达人精选区域。

商品遍历规则：如果在 `客户评论` 上方没有发现 `达人视频精选`，立即返回商品列表并换下一个未检查商品，禁止继续向评论下方搜索。如果发现一次完整的 `达人视频精选`，先记录商品和区域信息，然后立即返回商品列表，重新采集列表和控件；需要重新遍历时从商品列表重新开始，不继续停留在当前详情页处理其他区域。

如果页面底部固定栏或弹层遮挡目标区域，不得点击 `购买`、`立即购买`、`加入购物车` 或购物车图标来试探页面。TikTok 当前布局中，误点购买区域可能进入 `加入购物车` 页，而不是普通购买页。应先向上滑动让内容完全露出；商品卡片左侧图片只能作为一次性后备入口。若出现加入购物车页、购物车抽屉、商品规格或数量控件，禁止确认、结算或修改数量，立即使用当前页面新采集的关闭/取消/返回控件退出，并重新定位标题/价格文字区域。

当前已确认一种中间状态：`达人视频精选` 的标题或第一排缩略图被底部固定的 `购买`/`立即购买` 栏遮住一半。此时不能认为目标区域已经完整识别，也不能点击被遮挡区域。应向上滑动一次，让标题和第一个缩略图完全露出，再重新读取；只有完整可见时才读取数量或点击第一个视频。

第一条达人精选视频的点击位置应在 `达人视频精选` 标题正下方一点的第一张缩略图内。点击过低会落入 `评论`/评价区域并打开评论页；若发生误点，按一次返回后重新抓图定位，禁止重复原来的低位坐标。

如果目标区域不存在，不应点击推荐商品或其他视频来猜测。按当前任务的滚动上限结束该商品，返回列表检查下一个。

## 广告、推广和异常弹窗处理

TikTok Shop 常见阻塞页面包括：

- `TikTok Shop` 推广弹窗
- 加入购物车确认或购物车抽屉
- `分享主页` 弹层
- `发现好友` 页面
- 二维码扫描页
- 个人简介编辑页
- 图片查看器
- 登录、活动或优惠弹窗

处理规则：

1. 先重新截图并重新采集控件，确认弹窗属于当前页面。
2. 优先点击当前控件列表中名称为 `关闭`、`取消` 或明确的返回按钮。
3. 如果没有可靠关闭控件，使用一次 `KEYCODE_BACK`。
4. 每种弹窗最多尝试两次关闭动作。
5. 关闭后必须重新截图和采集控件，确认页面已经回到目标页面。
6. 如果连续两次关闭后页面仍没有变化，立即停止任务并报告异常，不要继续点击历史坐标。

特别注意：如果截图显示商品列表，但控件列表仍显示 `分享主页`、`发现好友` 或 `二维码` 控件，这说明截图和控件缓存不一致。此时不得点击这些控件，应先使控件缓存失效并重新采集；重新采集后仍不一致则退出当前任务。

广告或推广页的退出条件：

- 关闭后出现商品列表或商品详情页：继续任务。
- 关闭后回到个人主页：只在任务明确要求导航时继续，否则重新定位商店入口。
- 关闭后进入二维码/发现好友/简介编辑页：立即退出该页面，不执行其他操作。
- 弹窗无法关闭或页面状态连续两次不变：标记为 `unknown`，结束任务。

如果误点商品卡片导致出现 `已加入购物车`、`加入购物车`、`购物车`、`查看购物车` 或购物车抽屉，禁止点击确认、结算或购物车动作。使用当前页面新采集的 `关闭`、`取消` 或 `返回` 关闭后，确认回到商品列表，再重新采集商品卡片位置。下一次点击应避开图片和操作按钮，改点商品标题/价格右侧文字区域，不能重复使用原坐标。

如果出现 TikTok 请求访问通讯录、Facebook 好友、电子邮件或类似非必要权限的授权弹窗，直接点击当前页面新采集的 `不允许`，不要点击 `好的` 或授予权限。弹窗关闭后等待页面稳定，再重新采集截图和控件。

## 页面状态检查清单

每次动作前确认：

- 手机未锁屏；
- 当前 Activity 与预期页面相符；
- 截图和 UI 控件描述的是同一页面；
- 控件 ID 是本轮重新采集的，而不是历史 ID；
- 当前动作不会点击图片、视频、购买、购物车或管理控件；
- 页面没有广告、推广、分享或二维码弹窗；
- 动作执行后重新截图，确认页面真的发生了预期变化；Hybrid 页面跳转后等待 2-5 秒再判断；
- 个人主页进入商店时使用 `你的订单` 后面的商店图标，不使用底部通用 `商城`；
- 点击商品前确认截图和实时控件树都显示商品列表；
- 商品卡片点击前排除图片、购物车、购买和管理子区域；误进入购物车后先关闭并重新定位；
- ADB 返回成功只代表输入事件注入成功，不代表页面跳转成功。

## 当前限制

目前已经验证：

- Android ADB 连接
- Mobile MCP 数据和动作服务
- 本地视觉模型截图识别
- UFO Server/Client/WebSocket 链路
- 任务状态和 session ID 路由
- 商品列表读取
- 商品详情页滚动查找“达人视频精选”

目前仍未完成程序级的 TikTok 商品遍历控制器，因此不应把“逐个商品检查”完全交给 LLM 自主完成。要稳定支持完整遍历，需要后续增加：

- 页面类型检测
- 商品卡片结构化提取
- 详情页滚动计数器
- 返回列表验证
- 已检查商品账本
- UI 树与截图一致性校验
- 每个商品的独立状态保存

## 单步交互超时

每次页面跳转或恢复使用 60 秒 watchdog，包括进入个人主页、商店列表、商品详情、达人视频精选、视频页、达人主页，以及关闭广告/推广弹窗和重新采集截图控件。

如果 60 秒内没有出现预期页面特征：停止发送动作，记录 Activity、截图、控件、最后动作和耗时；最多执行一次明确恢复动作，页面仍不符合预期就返回 `failed/unknown`，不再等待全局 900 秒超时。下一次尝试必须使用新的 task name。

## 过程特征与报表要求

后续遍历达人视频时必须记录每个阶段的页面特征和动作结果，至少包括：

- 页面状态：个人主页、商品列表、商品详情、达人视频精选、视频页、达人主页、广告/推广弹窗或未知页面；
- 当前 Activity 和关键可见文字；
- 是否使用了新采集的控件；
- 执行的动作、动作结果和截图路径；
- 商品、精选视频和达人之间的关联关系；
- 页面特征不符合预期时的停止原因。

遇到以下任一情况立即退出当前任务，不继续猜测：截图和控件树不一致、进入其他商品、出现卖家工具页、加入购物车/购买页、广告或推广弹窗无法关闭、视频返回后没有恢复到同一商品的达人视频精选区域、视频索引无法与账本对应。
